# v2 测试规程（阶段 E）

2026-11-11 写定，打开测试集之前生效。本文规定阶段 E 的多种子运行、测试集评估和 MISOCP 参照怎么做。进度和结果记录仍写在 [TASKS.md](../TASKS.md)。

## 1. 原则

- 测试集指划分 A 的 48 个测试日（`configs/splits_v2.json` 的 `A_half_month.test`）。打开之前，方法、模型版本、超参数、经验库阈值和指标都按本文冻结。
- 测试结果出来后，不再根据测试结果修改任何方法或选择模型版本。运行中如果发现与方法无关的执行错误（例如崩溃、路径错误、记录缺字段），可以修复后重跑，并在记录中说明。凡是改变方法行为的修改，都要另开实验，不替换本规程下的结果。
- 测试阶段冻结经验库和 PPO 权重，关闭 Reflexion 和经验更新。
- 打开测试集后才想到的分析，一律标为"事后分析"。

## 2. 种子

- 正式使用 3 个训练种子：42（已完成）、43、44。每个种子都完整重建：PPO 预训练、两个 LLM 经验库（Proposed 和 No-Reflexion）、Pure-RL 日前代理，以及全部微调。
- 每个种子改变的是训练随机性：PPO 的初始化、采样和小批量顺序，以及预训练时的归一化抽样日（沿用 `train_ppo.py` 的种子 + 1）。LLM 每次调用的采样本身是随机的，接口不支持设种子，所以每个种子重建出的经验库自然不同。
- 下面这些数据侧设置在所有种子间保持不变，这样各种子之间的差别只来自训练和采样的随机性：
  - 预测噪声种子（`FORECAST_SEED`）；
  - 建库日的顺序（`ORDER_SEED = 2026`）和 6 个起步日；
  - 微调用的 150 个计划日的抽取（固定使用种子 42 的抽取结果）；
  - 预训练验证时使用的随机机械计划（种子 2026）。

## 3. 方法定义（所有种子相同）

| 方法 | 日前计划 | 日内 PV 无功 |
|---|---|---|
| Original | 中性计划（档位 0、电容器全关） | 零 |
| No-RL | Proposed 经验库检索 + LLM 生成 | 零 |
| No-LLM | 中性计划 | Proposed 第 150 回合策略 |
| No-PT | Proposed 经验库检索 + LLM 生成 | 从头训练 150 回合的策略 |
| No-Reflexion | No-Reflexion 经验库检索 + LLM 生成 | 用 No-Reflexion 计划预热 20 回合、微调 150 回合的策略 |
| Pure-RL | 日前 PPO 的确定性动作 | 用 Pure-RL 计划预热 20 回合、微调 150 回合的策略 |
| **Proposed** | Proposed 经验库检索 + LLM 生成 | 预热 20 回合、微调 150 回合的策略 |

- **预训练：** `train_ppo.py --config v2 --split-scheme A_half_month --variant improved --episodes 1500 --seed <s>`。
- **经验库：** 先用 6 个起步日从空库建起，再在 200 个正式日上续建，阈值 0.90。Proposed 每天生成初稿后做 3 轮 Reflexion；No-Reflexion 只生成初稿，不做反思。
- **Pure-RL 日前代理：** 设置同 T21，按 C2 顺序训练 200 个回合，种子为 s。
- **微调计划：** 在同样的 150 个计划日上生成，检索时排除同一日期，每天生成 1 次。
- **最终权重：** 所有微调组都用第 150 回合的权重，不按验证结果挑选。无预热对照只在种子 42 上保留，43 和 44 不再跑。
- **评估方式：** 策略取确定性动作，PV 无功按逆变器容量裁剪。机械计划必须通过计划解析器的约束检查。

## 4. 测试时的 LLM 调用

- 每个种子、每个测试日，分别用 Proposed 库和 No-Reflexion 库各生成 1 次计划。检索取最近的相似日，即使相似度低于阈值也照用。
- 生成参数同建库：DeepSeek-V4.1-Flash-1017、temperature 0.7、top_p 0.8、关闭 thinking，智算云接口。
- 允许最多 2 次格式修复，沿用现有 `generate_plan`。如果修复 2 次后仍不合法，当天改用中性计划，记为不合规。
- No-RL、No-PT 和 Proposed 共用同一份 Proposed 计划，No-Reflexion 用自己的计划，所以每个测试日每个种子只需 2 次调用。
- 每次调用都要记录：
  - token 数：接口返回的 prompt、completion 和 total tokens；
  - 响应时间：从发出请求到收到完整响应的墙钟秒数，每次尝试单独记录；
  - 重试次数和格式修复次数。

## 5. 指标与汇总

- **主指标：** 平均绝对电压偏差，即全节点、全 96 个时段的 |V − 1| 取平均，单位 p.u.。
- **次指标：**
  - 越限率：节点时段电压超出 0.95–1.05 p.u. 的比例；
  - 有越限的天数；
  - 全集最低和最高电压；
  - 每日 OLTC 换档次数和电容器投切次数；
  - 计划合规率（未修复即合法的比例，以及最终合法的比例）；
  - LLM 的 token 用量和响应时间（均值、中位数、P95，以及每日合计）。
- **汇总方式：**
  - 每个种子先对 48 天取平均。3 个种子再报告均值和样本标准差（n = 3）。
  - 逐日配对时，先对 3 个种子取平均，再在 48 天上算差值、标准误和更好/更差天数。
  - 另报告种子间方向是否一致，即 3 个种子的方法排序是否相同。

## 6. 执行顺序

1. 改代码，不改方法行为：
   - `finetune_ppo_v2.py` 和 `train_pure_rl_v2.py` 增加 `--seed`，计划日抽取固定为 42；
   - 验证脚本支持选择 `validation` 或 `test` 划分；
   - LLM 调用增加响应时间和尝试次数的记录；
   - 测试中的计划如果不合法，改用中性计划。

   改完后，用种子 42 的验证集结果核对：重算结果必须和 T20、T21 逐项一致。
2. 种子 43 和 44 完整重建，在 48 个验证日上跑全部方法，汇报 3 个种子的验证集均值和波动。**汇报经用户同意后，才进入第 3 步。**
3. 打开测试集：3 个种子 × 7 种方法 × 48 天。
4. MISOCP 参照（见第 7 节），可以和第 3 步同时跑。
5. C3 划分 B 检索泄露对照放在第 3 步之后。划分 B 的建库日和验证日会覆盖划分 A 的测试日，提前跑等于提前看到测试数据。
6. 汇总结果，改写 `docs/实验总览与改进方向.md`。

## 7. MISOCP 参照

- **定位：** 理想信息下的优化参照。它使用当天真实的 15 分钟负荷和光伏，不经过预测，联合优化 OLTC、电容器和 PV 无功。结果代回同一个 AC 潮流环境，用 AC 电压评分。它不参与任何方法的选择。
- **范围：** 48 个测试日全做，每天求解时限 600 秒。记录求解状态、MIP gap、求解时间，以及是否改用软限值。如果 0.95–1.05 硬限值模型不可行，就改用软限值模型，并在结果里单列标注。
- **先修再用：** v1 的普通日锥松弛解代回 AC 后出现了过压。打开测试集之前，先在训练日和验证日上排查锥松弛误差、电压平方目标和 AC 评分之间的差异，修正后冻结模型，再跑测试日。排查过程不使用测试日。

## 环境如何计算

- 使用冻结的 `models/case33bw.m`，直接读取原始欧姆阻抗和kW/kVAr负荷，分别换算后建立网络；32条闭合支路，根节点1，相角参考0，基准12.66 kV/10 MVA。
- 交流潮流主求解器为Newton–Raphson。独立构造复数节点导纳矩阵Ybus，以向电网注入为正，核对节点复功率和全网P/Q平衡，最大允许残差1e-7 MVA。
- OLTC按论文式(2)直接设置根电压 `1 + tap×0.006`；SC按式(3)提供固定0.15 MVAr注入，采用恒PQ元件，不使用随电压平方变化的电容器模型。
- PV无功范围为 `±0.3×sqrt(S²-P²)`，动作归一化到[-1,1]后乘当前范围。超额定有功和非法动作报错，不静默扩大容量或限发。
- 每天独立重置，初始OLTC零档、SC关闭、PV无功为零。00:00初始机械设置不计为后续调整；当天OLTC最多4次改变，SC各至多一个连续投入区间，机械计划按整小时切换。
- 原算例没有提供有效支路热额定值，本轮没有验证热限额，也没有把任意默认值当工程额定值。

`reset(date, plan)` 返回观测和说明；`step(q_fraction)` 返回观测、奖励、terminated、truncated和说明。观测含32维P负荷、32维Q负荷、33维电压、6维PV有功、6维当前无功及17维机械状态one-hot，共126维。

动作前电压由当前等效输入和上一步保持的无功计算；保持无功按当前能力限值投影。执行新动作后再计算本步奖励，避免把执行后的电压提前当输入。最终观测为第96步控制后的状态，不虚构下一天。

日内输入代表15分钟等效平均值，不声称真实控制起点已经知道随后15分钟平均功率；现场因果测量方案与3分钟细粒度合规仍需另行验证。

## 重跑方法

本机依赖位于 `D:\Codex\tools\llm-rl-voltage\.venv`；Python3.12.13、pandapower3.5.6、Matplotlib3.10.9。完整依赖见 [requirements-lock.txt](../requirements-lock.txt)。大型结果放D盘outputs，项目内保留代码与入口。

在项目根目录用PowerShell执行：

```powershell
$py = 'D:\Codex\tools\llm-rl-voltage\.venv\Scripts\python.exe'
& $py scripts/prepare_case33_data.py
& $py -m pytest -q
& $py scripts/run_environment_acceptance.py
```

第三条每次生成独立结果目录，并更新最新运行入口。可加 `--date 2012-03-20` 指定训练日；不会接受验证/测试日期作为这个环境验收脚本的选日。

新机器可先用uv建立Python3.12虚拟环境，再用 `uv pip install --python <该环境python路径> -r requirements-lock.txt` 安装依赖。无需启动MATLAB，不涉及LLM付费调用。

实现依据：[pandapower交流潮流](https://pandapower.readthedocs.io/en/latest/powerflow/ac.html)、[恒PQ注入及正负号](https://pandapower.readthedocs.io/en/latest/elements/sgen.html)。API签名也已核对本机安装版本。
